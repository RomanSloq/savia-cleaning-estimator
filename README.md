# Savia

Независимый портфолио-проект: одностраничный сайт вымышленного клинингового бренда Savia в Перми.

## Текущий этап

Stage 4B: форма отправляет заявку в `POST /api/lead`; сервер повторно валидирует данные и цену, затем передаёт заявку через заменяемый Telegram-адаптер. Страница остаётся статической, API выполняется по запросу.

## Рабочий процесс

1. Перед существенной работой прочитать `AGENTS.md`, этот файл и все документы в `docs/`.
2. Согласовать небольшой этап и перечислить файлы, которые планируется изменить.
3. Реализовать только согласованный scope.
4. Проверить релевантный пользовательский сценарий, адаптивность и доступность соразмерно этапу.
5. Обновить канонические документы, если изменились решения или фактическое состояние.
6. Показать изменения и результаты проверок. Commit и push выполнять только по явному разрешению.

## Локальная доставка заявок

Скопируйте `.env.example` в локальный `.env` и задайте серверные переменные:

```text
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Они читаются только серверным endpoint и не должны иметь префикс `PUBLIC_`. Без них сайт и сборка работают, но отправка формы честно возвращает ошибку конфигурации. Для production эти же значения задаются как environment variables проекта Vercel.

Маршрут заявки: браузер → `POST /api/lead` → серверная валидация и повторный `calculatePrice()` → Telegram Bot API. Клиентская цена не считается доверенной. Базовый honeypot снижает простейший автоматический спам; перед публичным запуском можно усилить защиту средствами платформы.
